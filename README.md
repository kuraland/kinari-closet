## 公開版

公開URL: https://kuraland.github.io/kinari-closet/

GitHub Pagesで公開しています。クラウド未設定または未ログイン時は、登録した写真や服の情報はGitHubへ送信されず、アクセスした端末のブラウザ内に保存されます。Supabaseを設定してログインすると、自分のスマートフォンとパソコンの間で同期できます。

## 起動

```bash
python3 -m http.server 4173
```

起動後、`http://localhost:4173` をブラウザで開きます。ビルドやパッケージのインストールは不要です。

## 初版でできること

- 写真付きの服の登録と編集
- 画像の軽量化、代表色とファイル名由来カテゴリの仮入力
- カテゴリ、色、季節、暖かさ、フォーマル度、在庫状態の管理
- 名前・色・メモの検索と絞り込み
- 気温、天気、予定、気分に応じたコーデ3案
- 「好き」「合わない」「着た」の履歴を次回スコアへ反映
- 直近7日に着た服を避けるオプション
- 削除の代わりにアーカイブ
- トップス、ボトムス、ワンピース、アウター、靴、小物の画像付きサンプルを各5点収録
- 実用性40%・服同士の相性15%を土台に、好みと流行の比率をスライダーで調整
- 「好き・合わない・着た」から、色・柄・素材・シルエット・テイストの傾向を学習
- 新しい評価ほど強く、予定・気分・気温が近い評価ほど強く反映
- 評価数が少ない間は好みスコアを中立へ寄せ、少数評価への過学習を抑制
- 3案を「総合バランス」「あなたらしさ」「今季をひとさじ」の役割別に選択
- トレンド情報に有効期限を設け、古い情報はスコアへの影響を自動縮小
- 好み／流行のバランス設定を端末内に保存
- コーデごとに実用性・好み・相性・今季らしさの採点内訳を表示
- 小物をコーデ候補へ追加
- サンプル30点をクローゼット画面からまとめて復元

## サンプルデータ

初回起動時に、画像付きのサンプル30点をブラウザ内へ追加します。既に登録済みの服は上書きせず、同じサンプルIDが保存済みの場合は重複登録しません。なくなった場合はクローゼット画面の「サンプル30点を復元」で再投入でき、ユーザー自身が登録した服や評価履歴はそのまま残ります。サンプルも通常の服と同じように編集・アーカイブでき、一覧では「サンプル」ラベルで識別できます。画像はこのMVP用に生成した無地・無ロゴの商品写真風素材です。

## 保存とプライバシー

服の写真・属性・評価は最初にIndexedDBへ保存するため、通信が一時的に切れても端末内で利用できます。Supabaseへログインした場合だけ、自分のユーザーID配下へ同期します。服データ・評価・設定はRow Level Securityで本人だけが読み書きでき、写真は非公開の`garment-images`バケットへ保存します。公開サイトへ置くのはRLS前提のanon keyだけで、管理者権限を持つ`service_role` keyは置きません。

## Supabaseの初期設定

1. Supabaseで無料プロジェクトを1つ作成します。
2. SQL Editorで`supabase/migrations/202609290001_initial_schema.sql`を実行します。
3. Project SettingsのAPI画面からProject URLと公開用Publishable key（旧形式ではanon key）を確認します。
4. `supabase-config.js`へ次のように設定します。プロパティ名は互換性のため`anonKey`ですが、Publishable keyもそのまま使えます。

```js
window.KINARI_SUPABASE_CONFIG = Object.freeze({
  url: "https://YOUR_PROJECT.supabase.co",
  anonKey: "YOUR_PUBLIC_ANON_KEY",
});
```

5. AuthenticationのURL Configurationで、公開URL`https://kuraland.github.io/kinari-closet/`をSite URLとRedirect URLへ追加します。

ログイン後の同期は最終更新日時によるLast Write Winsです。端末にしかない服はクラウドへ追加し、クラウドにしかない服は端末へ復元します。サンプル30点は各端末に同梱済みなので同期対象外です。アーカイブを削除の代わりに使い、別端末から意図せず復活することを防ぎます。

変換処理のテストは`node scripts/test-cloud-sync.cjs`で実行できます。

## 現時点の「AI」の範囲

公開中の静的サイトへ秘密のAPIキーを置かないため、外部の生成AI APIは使っていません。写真からの入力補助は簡易画像解析と名前由来の属性推定です。コーデは①実用ルールによる候補生成、②色・柄・素材・シルエットの相性、③評価履歴から作る個人別の特徴量、④`trends.json`の今季情報、を組み合わせた説明可能なハイブリッド推薦です。

今季トレンドはアプリ本体から分離しており、`trends.json`を更新すれば推薦へ反映できます。`updatedAt`と`validUntil`から鮮度を判定し、期限切れの情報は中立点へ寄せて影響を自動的に弱めます。2026年秋冬の初期設定は、[VogueのFall 2026 trend report](https://www.vogue.com/article/fall-winter-2026-fashion-trends)が示す「クラシックの再解釈、強い色、豊かな質感、大胆なプロポーション」を、手持ち服に適用できる属性へ置き換えています。

`.github/workflows/trend-refresh.yml`は毎週月曜に、WEARの総合・メンズ・レディース各「トレンドキーワード」公開ページを低頻度で取得します。保存対象は短い公開キーワードと集計結果だけで、画像・投稿本文・ユーザー名・プロフィールは取得しません。キーワードを色・柄・素材・シルエット・テイストへルール変換し、2ページ以上の取得、8語以上のサンプル、一定以上の信号が揃った場合だけ`trends.json`の更新案をPull Requestにします。自動マージはせず、内容を確認してから反映します。

初回だけ、GitHubリポジトリの「Settings → Actions → General → Workflow permissions」で書き込み権限とPull Request作成を許可してください。以後は自動実行され、変更がある週だけ確認用Pull Requestが作られます。WEAR側のページ構造・利用条件が変わった場合は、収集処理を停止して見直してください。

`.github/workflows/trend-freshness.yml`は週1回トレンド情報の期限を検査します。期限切れになるとGitHub Actionsが失敗するため、古い流行情報が気づかれないまま残ることを防げます。サイト構造の変更などで収集に失敗した場合も、既存データは更新されません。

ローカルで変換ロジックだけ確認する場合は`node scripts/test-update-trends.mjs`、実際の公開ページから更新内容をプレビューする場合は`node scripts/update-trends.mjs`を実行します。`--write`を付けたときだけ`trends.json`と`data/trend-snapshot.json`を書き換えます。

好み学習では、最近の評価ほど強く残る120日半減の時間減衰を使います。また、現在選んだ予定・気分・気温と近い過去評価を少し強く評価します。これにより「仕事ではきれいめ、休日はカジュアル」のような場面別の好みを、単一の嗜好へ潰しにくくしています。
